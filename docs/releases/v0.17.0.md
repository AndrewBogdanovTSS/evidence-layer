## evidence-layer 0.17.0

A test runner's arguments no longer decide what kind of run it was. Nothing
here changes what an exit code means.

### Artifacts

- **Once a command reaches a test runner, everything after it - up to the
  next `&&`, `||`, `;` or `|` - is the runner's arguments.** 0.14.0 stopped reading paths as part of the
  invocation, but an unquoted, path-free argument was still read: `pnpm test
  eslint` - a vitest filter for an `eslint/` directory - and `pnpm test -t
  lint` were classified `lint`, and `pnpm test -t typecheck` `types`. A test
  run classified `lint` had its test summary read as the wrong kind of run, so
  `claims` rejected every success claim on it. Now `pnpm test`, `pnpm run
  test`, `npm test`, `vitest`, `npx vitest`, `pnpm vitest`, `jest`, `mocha`,
  `python -m pytest`, `rspec`, `phpunit` and a `test:*` package script are
  `tests` whatever follows them - also when run through an interpreter, as in
  `node node_modules/vitest/vitest.mjs run lint`.
- Any other program's path-free arguments are still read - they are how
  `nuxt typecheck`, `git diff` and `pnpm install --frozen-lockfile` are told
  apart - and each part of `a && b` is read on its own: `pnpm lint && pnpm
  test eslint` is still `lint`.
- The 0.14.0 advice to quote such an argument no longer applies to test
  runners.

### Behaviour changes to check when upgrading

- **Some artifact ids change.** The kind is the id's prefix, so a test-runner
  command whose kind came from a path-free argument - `pnpm test eslint`, once
  `lint-…`, or `pnpm test -t typecheck`, once `types-…`, now `tests-…` - gets a
  different id. An artifact generated with an earlier version and verified
  with this one fails its address check for those commands only; regenerate
  the evidence. Commands whose kind did not change keep their ids.
- **Success claims on those runs are now held to their test summary**, as
  any other test run's are.
