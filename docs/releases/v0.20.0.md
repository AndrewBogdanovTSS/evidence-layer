## evidence-layer 0.20.0

The first half of Phase 1 of
[the roadmap](../plans/review-and-roadmap-2026-11.md): rules that guessed now
read what the gatherer knew, the receipt is written rather than typed, and
captured output is redacted. From this release,
[`docs/compatibility.md`](../compatibility.md) says what a project may build
on - and it is why this page opens the way it does.

### What you may have to do

- **A claim over a failing run must say the run failed.** A `VERIFIED` claim
  citing a run that exited non-zero is now `claims/failing-run` unless it
  admits the failure - with a predicate a clean run would not satisfy
  (`exit=1`, `exit!=0`, `failed>=1`) or in words ("reports failures", "does
  not pass"). The finding's `fix` is the grounding line with the run's own
  predicates; your sentence stays as written. Claims the skeleton wrote
  already carry them.
- **Some artifact ids change their first half.** A test, lint or typecheck
  step whose command the package did not recognise - `npm run check`,
  `make check`, `python -m unittest`, `cargo clippy`, `biome check` - used to
  be gathered as `cmd-a3f91c`. It is now `tests-a3f91c` (or `lint-`,
  `types-`), and held to that kind's rules: a success claim over it needs the
  run to have checked something. The six hex digits do not change. Gather
  again and cite the new id; `seal/not-gathered` names it.
- **The runtime gate says when a review has no Access Receipt.** A changed
  review with claims and no receipt gets `receipt/absent`, `unverifiable` -
  a message by default, a block under `--strict`. Copy the "Suggested access
  receipt" from the bundle, which this release starts writing.
- **`claims --strict` fails a review that reports a result in prose.** "All
  12 tests pass" outside any `**Claim**:` line is a new warning,
  `claims/unclaimed-result`. State it as a claim, or mark it `UNVERIFIED`.
- **Run `evidence-layer init claude` (or `init codex`) again, and commit the
  new file.** The hooks now run a launcher `init` writes beside the
  configuration, `.claude/evidence-layer-hook.mjs` or
  `.codex/evidence-layer-hook.mjs`. Hooks written by an earlier release keep
  working as they did - including failing with "Cannot find module" where the
  package is not installed.
- **A step's output may now read `[REDACTED:<NAME>]`** where it printed the
  value of a secret-named environment variable, and that step's id differs
  from what 0.19.0 gave the same run.

### Gathering

- **The gatherer writes the Access Receipt.** The bundle has a "Suggested
  access receipt": branch, head, target, the merge-base with
  `origin/<target>` and the size of that diff, read from git. `Files opened
  during review` starts at 0 until you say otherwise. Gathered against
  something that is not a branch on `origin`, it writes no field and says
  why. Before this the receipt was typed by hand, though the documentation
  said otherwise.
- **The step says what an unrecognised command is.** The kind half of an id
  comes from the command when the package recognises it, and from the step
  that ran it when it does not. Rules read the kind from the id
  (`artifactKind`). A lint step that runs the typechecker is still one
  typecheck artifact.
- **Redaction.** The value of every environment variable named as a secret -
  a whole `_`-separated `TOKEN`, `SECRET`, `PASSWORD`, `PASSPHRASE` or
  `CREDENTIALS`, or a trailing `_KEY` - is replaced with `[REDACTED:<NAME>]`
  in each captured command line and output, before the summary, the id, the
  bundle and the seal. `gatherEvidence({ redact })` runs after it for the
  rest. Values under eight characters are left alone.

### Claims

- **New rule `claims/failing-run`** - above.
- **New observation `claims/unclaimed-result`.** A sentence that names a kind
  of run and reads as its outcome, outside any claim, is a warning in a
  review file. Whether the layer should ever do more about it is
  [DEC-0014](../decisions/0014-results-stated-as-prose.md), proposed.

### The runtime gate

- **A result reported as prose is counted.** A final reply's unclaimed
  results go on the stop's journal entry as `gate.unclaimed`, with the
  sentences. Nothing is said to the agent and nothing is blocked.
  `journal report --include-gate` lists those stops by id;
  `journal tag <id> real|false --gate` marks one.
- **`receipt/absent`** - above.
- **A fresh clone is told the gate is inactive.** A hook that ran the package
  straight out of `node_modules` failed with exit 1 before the project's
  install step - a broken hook to the host, an ungated session to everyone
  else, and nothing said. The launcher `init` now writes finds the package,
  and where there is none says so through the hook protocol: at session
  start the agent reads that the gate is inactive and how to change that,
  and under `--fail-closed` or `--strict` a stop is blocked. It is the file
  the Claude Code plugin already ran. Codex on Windows still uses
  `npx --no-install`, and still fails rather than explains.

### Repository

- `docs/compatibility.md`, and the package's exports pinned in
  `test/fixtures/exports.json`: an export added without a line there fails
  the suite.
- `check:ladder` warns on a `fix:` commit with no `Missed-By:` trailer.
  `Missed-By: none` is the answer for a bug no review let through, and is not
  recorded as a miss.
- The roadmap was reviewed and revised; what changed and why is at its head.

New codes: `claims/failing-run`, `claims/unclaimed-result`, `receipt/absent`.
New exports: `artifactKind`, `commandKind`, `admitsFailure`,
`failingRunProblem`, `readsAsFailure`, `generateReceiptSkeleton`,
`unclaimedResults`, `UNCLAIMED_PREFIX`, `readMissedBy`, `isFixCommit`.
