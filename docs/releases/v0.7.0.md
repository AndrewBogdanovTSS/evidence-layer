## evidence-layer 0.7.0

The checks now run in GitHub Actions as one workflow step, and put each
finding on the line it is about. Until now CI meant a `run:` step and a reader
opening the log to find out why the job was red. The decision is
[DEC-0007](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0007-github-action.md).
Nothing here changes what a review must contain or what any exit code means.

### The GitHub Action

```yaml
- uses: actions/checkout@v5
- uses: AndrewBogdanovTSS/evidence-layer@v0.7.0
  with:
    claims: review.md            # comma- or newline-separated
    # receipt: review.md         # needs fetch-depth: 0 and the target branch
    # governance: 'true'         # also run governance --enforce
    # strict: 'true'             # warnings and unverifiable fail too
```

- Every finding that is not a pass becomes an annotation on its line, titled
  by its [reason code](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/evidence-layer.md#machine-readable-output),
  and the job summary lists them. `unverifiable` and `flaky` are warnings
  whose title says which, so "nobody could check this" does not read as a nit.
- It runs the evidence-layer the project installed, so CI and a laptop give
  the same verdict. With none installed, it runs the exact version the action
  was released with - `@v0.7.0` runs 0.7.0, next year too - or the `version`
  input; never `latest`.
- Outputs `exit-code` and `conclusion` (`success`, `failure`, `flaky`,
  `misconfigured`). Nothing to check, a missing review file, an installed
  package too old to annotate, or a version that is not exact is
  `misconfigured`, exit 2, and outranks a failure - a step that could not run
  never passes.
- No token and no permissions: annotations are workflow commands, so they land
  on the job's own check run with nothing to grant.
- A plain Node script with no dependencies and no build, so the action runs
  straight from this repository at the tag a workflow names.

### `--format github`

- `claims`, `receipt` and `governance` take `--format github` for any `run:`
  step: the annotations, then the usual text report, then a job summary when
  `GITHUB_STEP_SUMMARY` is set. The exit code is the text mode's.
- **A review cannot give the runner instructions.** It is text written by an
  agent or by the author of a pull request from a fork, and the runner obeys
  any stdout line that reads like `::add-mask::...`. Annotation values are
  escaped the way the runner un-escapes them, so a newline cannot start a
  second command, and the text report - which quotes the review - runs under
  `::stop-commands::` with a token chosen at random for each run.

### Publishing

- Releases are published through npm's Trusted Publisher: the workflow's OIDC
  token is the only credential, and there is no long-lived npm token to leak
  or renew. 0.6.0 was the first release published this way; with the token
  gone, a broken Trusted Publisher fails the publish rather than falling back.

### API

- New exports: `annotations`, `escapeData`, `escapeProperty`, `stopToken` and
  `renderFindingsSummary`; `printFindings`, which every check uses to print in
  the format asked for. `Format` gains `'github'`.
- `package.json` declares `"evidenceLayer": { "outputFormats": ["text",
  "json", "github"] }` alongside `hookProtocol` - the capability the action
  checks instead of comparing versions.

### Repository

- CI runs the action on a fixture review with `uses: ./`, so each commit's
  action and checks are tested together.
- The suite is 377 tests across 29 files.
