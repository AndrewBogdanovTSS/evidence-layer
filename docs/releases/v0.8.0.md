## evidence-layer 0.8.0

The runtime gate now runs in Codex as well as Claude Code, a gathered test
step records how many tests it ran, and `init --review` no longer writes a
command a shell could be turned against. Nothing here changes what a review
must contain or what any exit code means.

### Security: `init --review` could write a command that runs code

In 0.5.0 to 0.7.0, `evidence-layer init claude --review <paths>` put the value
on the hook's command line inside double quotes, which a POSIX shell still
expands. `--review '$(touch x)'` wrote hooks that ran `touch x` every time
one of them ran, for everyone who checked the settings out. The value
is an argument to `init`, so it takes someone - or an agent - running `init`
with a crafted value, and the result is committed where others run it.

`init claude|codex` now refuses a `--review` value with any character other
than letters, digits and `. _ / , @ + -`: it exits 2 and writes nothing.

**What to do:** look at the `--review` part of the evidence-layer commands in
`.claude/settings.json` (and `.claude/settings.local.json`). Plain paths are
fine. Anything else - `$`, a backtick, `;`, `|`, `&`, a quote - should be
removed: run `init` again with plain paths, which replaces evidence-layer's
own entries and keeps every other hook.

The rest of the hook path was tested against the same attack and needed no
fix: for both hosts and every event, a payload in every field the agent
writes - a session id, a written path, a patch's paths, a review's claims
and receipt, the final message - and a repository directory itself named
`$(...)`, with nothing run (`test/host-injection.test.ts`).

### The runtime gate in Codex

```bash
npx evidence-layer init codex     # writes .codex/hooks.json; approve the hooks in /hooks
```

- The same three hooks as Claude Code: session start, before a file write,
  and stop, with the same decisions. [DEC-0009](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0009-codex-host.md)
  records why Codex is supported now.
- Codex edits files with `apply_patch`, so the guard on the evidence ledger
  reads every path a patch adds, updates, deletes or moves a file to.
- Codex gives a hook no project directory, so the command finds the package
  from `git rev-parse --show-toplevel`, as Codex's documentation does; on
  Windows it uses `npx --no-install`. Codex runs a project's hooks only once
  they are trusted, and again after `init` changes them.

### Work summaries: how much a test step checked

`VERIFIED[tests-…: passed>=N]` reads a `[SUMMARY tests: …]` line, and until
now nothing wrote one. [DEC-0008](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0008-work-summaries-have-a-writer.md):

```js
import { gatherEvidence } from 'evidence-layer'
import { summariseVitest } from 'evidence-layer/adapters/test-reports'

await gatherEvidence({ repo, base, summaries: { test: summariseVitest() } })
```

- New entry point `evidence-layer/adapters/test-reports`: `summariseJUnit`
  (JUnit XML - pytest, Maven, Gradle, `dotnet test`, go-junit-report,
  jest-junit), `summarisePytest`, `summariseVitest` and `summariseNodeTest`
  (`node --test`), and the parsers under them. A JUnit report older than the
  step is refused, so an earlier run's counts are never credited to this one.
- The bundle's suggested claims then carry the counts:
  `VERIFIED[tests-…: exit=0, passed>=3, failed=0]`.
- `PlanOptions` takes `testCommand` and `typecheckCommand`, so a project not
  on pnpm can gather. pytest, rspec, phpunit, mypy, pyright, ruff, flake8
  and pylint are recognised for what they are; pytest used to be a plain
  command, held to none of the test rules.

### Fixed

- The GitHub Action ref the README shows (`@v0.7.0`) would have stayed behind
  at every release. `check:docs` now holds it to the package version and the
  release rewrites it, so the snippet above names this release.
- The build's type-resolution check (attw) only warned; it fails now. The
  boundary test now also sees `export … from` and `import()`.

### The example project

`examples/plain-node-project` is set up the way a project using this package
should be: an evidence script with work summaries, the action in CI, and the
hooks for both hosts. Inside this repository it is a template - git answers
for evidence-layer there - so `npm run standalone` copies it out as a
repository of its own, where the gate and the seal work on it.

### Repository

- `check:ladder` runs in CI on every commit a push or pull request brings.
- The action's download-the-release path runs in CI, through real `npx`, in
  a workspace with nothing installed.
- Freshness is tested for deletes, renames, mode changes and symlinks.
- The suite is 425 tests across 34 files.
