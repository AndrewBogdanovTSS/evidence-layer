## evidence-layer 0.13.0

Misses can be recorded from the history of a given ref instead of `HEAD`.
Nothing here changes what an exit code means.

### Misses

- **`recordNewMisses(repo, journal, { ref })` and `findMisses(repo, { ref })`**
  read the history of `ref` - typically the branch a pull request targets. A
  branch merged by squash loses its own commits: a miss recorded from a pull
  request branch's own commit would name a SHA the main branch never contains,
  and the squash commit carrying the same trailer would later be recorded as a
  second miss. Recording from the target's history counts each miss once, by
  the commit that landed.
- A ref git cannot resolve throws instead of returning no misses: "none" and
  "could not read the history" are different answers. Without a ref, a
  directory that is not a repository still yields none, as before.
- History is read through `git()` with an argument array and
  `--end-of-options`, so a ref is never seen by a shell or read as a flag.

### API

- New: `MissesOptions`. `findMisses` and `recordNewMisses` take an optional
  `MissesOptions`.
