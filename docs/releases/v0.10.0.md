## evidence-layer 0.10.0

Fixes from an independent review of the runtime gate, the gatherer and the
seal - the path that runs inside an agent's session. The gate now says each
thing once, names the command and base it wants gathered with, and costs one
tree fingerprint per stop instead of one per checked text. The gatherer's idea
of "the change" now includes what is not committed yet, and each step can have
its own timeout. Nothing here changes what an exit code means.

Four changes in the same review alter what the gate accepts rather than fix a
bug - what a stop checks, which runs a claim may cite, a `restamp` command,
and what a fence's commit label means. They are drafted as a proposal in
`docs/decisions/0010-gate-scope-and-run-identity.md`, not implemented.

### The runtime gate

- **Warnings get their own lines.** An allow whose only findings were warnings
  (`claims/shotgun`, a stale `git diff` block) printed "not everything could be
  checked:" and then nothing. Every non-pass finding is now listed, worst
  first, and an allow without unverifiable findings says "these need a look".
- **An exhausted episode speaks once.** After a retry episode spent its blocks,
  every later stop repeated the same `systemMessage` and journalled another
  `retry-exhausted` allow. While the checked texts, the sealed run, the tree
  and the findings are what they were at the last verdict, a stop now says
  nothing and journals nothing. Any change - an edit to the review, a new
  gather, an edit to the code a cited run describes, a fetch that changes a
  receipt's base check - and it speaks again.
- **A stop with nothing left to check closes the episode.** When the claims
  that opened an episode are gone (the review deleted or put back, the final
  message making none), the episode closes and is journalled with the new
  outcome `closed-unchecked` - an `unverifiable` entry, never a clean check.
  A later failure starts a fresh episode, with fresh blocks.
- **Untagged blocks are listed, for the person.** `journal report
  --include-gate` lists every block not tagged yet, newest first - id, time,
  scope, first finding - so `journal tag <id> real|false --gate` needs no
  reading of the JSONL. It also counts `closed-unchecked` episodes on their own
  line: an upper bound on blocks escaped by dropping the claims, since a change
  of subject after a block counts too. The id is never put in a block's
  reason: the agent reads the reason, and the blocked party must not be handed
  the command that grades its own block.
- **The gather command is named, with its base.** Session start, a block and
  `seal/no-run` say which command gathers evidence instead of "the project's
  evidence script". Set it once in package.json:

  ```json
  { "evidenceLayer": { "gather": "pnpm evidence --base origin/main" } }
  ```

  Without it, the gate names the command the current run recorded, or - for a
  project with an `evidence` script - `<package manager> run evidence`, from
  its `packageManager` field (npm when there is none). When a run exists, the
  base it was gathered against is named too.
- **One fingerprint per stop.** Checking a review and a final message used to
  fingerprint the tree once per text, and find the repository and its state
  directory again for each check and each journal write. A stop now resolves
  them once.
- **`seal/not-gathered` says where the block came from.** It names the kept run
  that produced the cited id, when one is still kept, and the id the current
  run gave the same command. A final message citing an unknown id is told the
  id is not in "the current sealed run", not in "this document".

### The gatherer

- **Uncommitted and untracked changes are part of the change.** The plan (a
  scoped `lintCommand`, `testGate`) and `GatherResult.changedFiles` used to see
  only `git diff base...head`. They now also get every tracked edit and
  untracked file on top of the reviewed commit, minus the review and the
  bundle. The diff block keeps describing the commits, so its id does not
  move; tracked edits get a `## uncommitted` block (`git diff --stat HEAD`),
  and new files are in the working-tree block. `GatherResult.committedFiles`
  holds the commits' part alone. The header says how many files are not
  committed.
- **Per-step timeouts.** `GatherOptions.timeoutMs` takes one number for every
  step or one per step name (`{ test: 900_000 }`); the default stays 300
  seconds. The README's "at your project's own gates and timeouts" is now
  true.
- **The bundle header names the gather command and base** - from
  `GatherOptions.gatherCommand` or package.json, as above - instead of always
  "`pnpm evidence`", and the seal records both (`Seal.gatherCommand`,
  `Seal.base`) for the gate to name.
- **Each artifact block is printed once.** A block that backs a suggested claim
  is printed under *Suggested claims* with that claim; its step's section
  points there. Two steps running one command give one claim.
- **A bundle written to another Windows drive is sealed.** With `--out` on a
  drive other than the repository's, the path was not recognised as outside
  the repository, git refused to leave it out of the fingerprint, and the
  gather ended "not sealed: could not drop the excluded paths". Such a path is
  now left out like any other outside path.

### Behaviour changes to check when upgrading

- A scoped lint or test gate that relied on seeing committed files only now
  also gets uncommitted and untracked ones; `committedFiles` has the old list.
- A dirty tree adds a `## uncommitted` block to the bundle.
- A tool that read a step's block out of its own section of the bundle finds
  a pointer there now; the block is under *Suggested claims*.
- Sample-integrity quotes are pre-filled for committed files only, since
  `receipt` checks them at the reviewed commit.
- `summariseGate` counts `closed-unchecked` as `closedUnchecked`, not among
  `degradedAllows`.

### API

- New: `gatherCommandFor(root, recorded?)`, `GatherOptions.gatherCommand`,
  `GatherOptions.timeoutMs`, `GatherResult.committedFiles`,
  `Seal.gatherCommand`, `Seal.base`, `LintOptions.artifactSourceName`,
  `untaggedBlocks(entries)`, `GateSummary.closedUnchecked`, and the gate
  outcome `closed-unchecked`.
- `sourceFingerprint` takes the repository root and `readCurrentRun` the state
  directory, `checkFreshness` a fingerprint already taken - each optional, for
  a caller that has it.
