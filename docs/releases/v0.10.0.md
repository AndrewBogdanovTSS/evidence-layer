## evidence-layer 0.10.0

Fixes from an independent review of the runtime gate, the gatherer and the
seal - the path that runs inside an agent's session. The gate now says each
thing once, names the command it wants run and the journal entry it wrote, and
costs one tree fingerprint per stop instead of one per checked text. The
gatherer's idea of "the change" now includes what is not committed yet. Nothing
here changes what an exit code means.

Three findings of the same review question the design rather than the code -
what a stop checks, which runs a claim may cite, and what identifies a block.
They are drafted as a proposal in
`docs/decisions/0010-gate-scope-and-run-identity.md`, not implemented.

### The runtime gate

- **Warnings get their own lines.** An allow whose only findings were warnings
  (`claims/shotgun`, a stale `git diff` block) printed "not everything could be
  checked:" and then nothing. Warnings are now listed after the problems, and
  that allow says "there are warnings".
- **An exhausted episode speaks once.** After a retry episode spent its blocks,
  every later stop repeated the same `systemMessage` and journalled another
  `retry-exhausted` allow. While the checked texts, the sealed run and the tree
  are what they were at the last verdict, a stop now says nothing and journals
  nothing. Any change - an edit to the review, a new gather, an edit to the
  code a cited run describes - and it speaks again.
- **A stop with nothing left to check closes the episode.** When the claims
  that opened an episode are gone (the review is back to what it was, the final
  message makes none), the episode closes and is journalled with the new
  outcome `closed-unchecked` - an `unverifiable` entry, never a clean check -
  so its spent blocks no longer carry over to a later, unrelated failure.
- **Block reasons name their journal entry.** Each block ends with
  `evidence-layer journal tag <id> real|false --gate`, the id already filled
  in; `journal report --include-gate` lists every block not tagged yet, with
  its time and first finding.
- **The gather command is named.** Session start, a block and `seal/no-run`
  say which command gathers evidence instead of "the project's evidence
  script". Set it once in package.json:

  ```json
  { "evidenceLayer": { "gather": "pnpm evidence --base origin/main" } }
  ```

  Without it, a project with an `evidence` script gets `<package manager> run
  evidence`, from its `packageManager` field (npm when there is none).
- **One fingerprint per stop.** Checking a review and a final message used to
  fingerprint the tree once per text, and find the repository and its state
  directory again for each check and each journal write. A stop now resolves
  them once.
- **`seal/not-gathered` says where the block came from.** It names the kept run
  that produced the cited id, when one is still kept, and the id the current
  run gave the same command. A final message citing an unknown id is told the
  id is not in "the current sealed run", not in "this document".

### The gatherer

- **Uncommitted and untracked changes are part of the change.** The plan (a
  scoped `lintCommand`, `testGate`) and `GatherResult.changedFiles` used to see
  only `git diff base...head`. They now also get every tracked edit and
  untracked file on top of the reviewed commit, minus the review and the
  bundle. With anything uncommitted, the diff block becomes `git diff --stat
  <merge-base> <tree>`, the tree being the one the steps ran against, so a new
  file shows there too. The header says how many files are not committed.
- **The bundle header names the gather command** - `GatherOptions.gatherCommand`,
  or the package.json setting above - instead of always "`pnpm evidence`".
- **Each artifact block is printed once.** A block that backs a suggested claim
  is printed under *Suggested claims* with that claim; its step's section
  points there. Two steps running one command give one claim.

### Behaviour changes to check when upgrading

- A scoped lint or test gate that relied on seeing committed files only now
  also gets uncommitted and untracked ones.
- With uncommitted changes, the diff block's command - and so its id - is
  different from before. A clean tree gives the same block as 0.9.0.
- A tool that read a step's block out of its own section of the bundle finds
  a pointer there now; the block is under *Suggested claims*.
- Sample-integrity quotes are pre-filled for committed files only, since
  `receipt` checks them at the reviewed commit.

### API

- New: `gatherCommandFor(root)`, `GatherOptions.gatherCommand`,
  `LintOptions.artifactSourceName`, `newEntryId()`, `untaggedBlocks(entries)`,
  and the gate outcome `closed-unchecked`.
- `appendEntry` accepts an `id`. `sourceFingerprint` takes the repository root
  and `readCurrentRun` the state directory, `checkFreshness` a fingerprint
  already taken - each optional, for a caller that has it.
