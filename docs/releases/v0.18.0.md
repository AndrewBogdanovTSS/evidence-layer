## evidence-layer 0.18.0

Azure Pipelines, as a place to run the checks and as a place `governance`
reads triggers from. Nothing here changes what an exit code means.

### Output

- **`--format azure`** on `claims`, `receipt` and `governance`: one
  `##vso[task.logissue]` per finding that is not a pass - an error, or a
  warning whose message opens with `unverifiable` or `flaky` - with its file,
  line and code, then the text report, then, on an agent, the summary attached
  to the run with `task.uploadsummary`. The exit code is the text mode's.
- **Review text cannot command the agent.** Azure's agent obeys `##vso[`
  anywhere in a line and has nothing like `::stop-commands::`, so under
  `--format azure` every piece of review text printed - the report, the
  issues, `governance`'s JSON block - is defanged: a zero-width space between
  the two `#`s, and `#` inside the JSON block, which parses back to the
  same text ([DEC-0012](../decisions/0012-azure-pipelines-output.md)).
  `--format text` and `json` print the review as written; in an Azure step,
  use `azure`.
- `evidenceLayer.outputFormats` lists `azure`, for launchers that check the
  capability rather than a version.

### Governance

- **Azure Pipelines files are triggers**: `azure-pipelines*.yml` at the root,
  YAML under `.azure-pipelines/`, `azure-pipelines/`, `.azuredevops/` and
  `.pipelines/`, and the local templates they include
  ([DEC-0013](../decisions/0013-governance-reads-azure-pipelines.md)).
- **simple-git-hooks is a trigger**: the hooks `package.json`'s
  `simple-git-hooks` field, `.simple-git-hooks.json` or `simple-git-hooks.json`
  declares. Its `.js` and `.cjs` configurations are code and are not read.
- **`governance/reached` names the trigger it rests on** - and, for an Azure
  file, says that it runs once a pipeline in Azure DevOps points at it, which
  no file shows.
- **New code `governance/template-unread`**, `unverifiable`: an invariant
  nothing readable reaches, while a pipeline template from another repository,
  with a computed path, or missing could not be read.
- `triggerSources` and `traceTriggers` are exported; `reachableCommands` is
  unchanged.

### The example

- `examples/plain-node-project/azure-pipelines.yml`: the gather - review -
  verify layout for Azure Pipelines, each job posting its own pull request
  status through `scripts/azure-pr.mjs`, so a status policy can require
  `evidence` and `governance` while the review stays optional.
- `npm run ci:local -- --pipeline azure` runs it locally, the model step read
  out of the pipeline's `claude -p` script.

### Behaviour changes to check when upgrading

- **An invariant only a pipeline file or simple-git-hooks reached was
  `governance/unreached`, an error; it now passes.** Under `--enforce`, a run
  that failed for that reason alone exits 0.
- **With an unreadable Azure template in the repository, an unreached
  invariant is `unverifiable`, not an error** - under `--enforce` that exits 0
  where it exited 1. The finding names the templates.
- The details of `governance/reached` findings changed wording; anything that
  matches on the sentence rather than the code should match on the code.
