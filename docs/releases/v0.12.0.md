## evidence-layer 0.12.0

Recording a miss is now deterministic. Every field of a journal line made from
a `Missed-By:` trailer comes from the fixing commit, so any checkout of the
same history writes the same lines in the same order. A project whose main
branch only takes pull requests can record misses from each pull request
branch instead of from one machine. Nothing here changes what an exit code
means.

### Misses

- **A miss's id is its commit.** `recordNewMisses` writes the fixing commit's
  first eight hex digits as the entry id (`missEntryId`), and its committer
  date as `ts`. Random ids made the same miss a different line on every
  machine that recorded it, so two branches that both recorded it merged two
  entries and the floor counted it twice. Identical lines from two branches
  merge as one.
- **Oldest first.** New misses are appended in commit order, not `git log`'s
  newest-first order, so the journal reads in time order.
- Misses recorded before this release keep their random ids; the dedupe still
  keys on the commit, so nothing is recorded twice.

### API

- New: `missEntryId`. `ExtractedMiss` has an optional `date`;
  `parseMissesFromLog` reads `%H<FS>%cI<FS>%B<RS>` and still reads the older
  two-field form.
- `appendEntry` accepts an optional `id`; without one it generates a random id
  as before.
