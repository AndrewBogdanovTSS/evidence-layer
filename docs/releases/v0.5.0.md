## evidence-layer 0.5.0

Until now every check ran in CI, after the change and its account were
written - and usually after someone had started reading them. 0.5.0 adds the
moment before that: a runtime gate that checks an agent's claims when it tries
to stop, so the agent that wrote "the suite passes" is the one that fixes it.
It also closes a shell-injection hole in `receipt` that every earlier version
has. The decision, its threat model and its invariants are
[DEC-0005](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0005-runtime-gate.md);
why each choice was made is in the
[implementation report](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/plans/runtime-gate-implementation-report.md).

### Security

- **`receipt` no longer runs anything a review says.** It built git commands by
  concatenating the receipt's `Target branch` and every Sample integrity path
  into a shell string, so a review containing `$(...)` executed it on the
  machine checking it - in CI, a pull request from a fork. Git is now called
  with an argument array and no shell (`git()` / `gitCapture()` in the API),
  `gatherEvidence` passes caller-supplied revisions after `--end-of-options`,
  and changed paths are read NUL-separated. **Upgrade if you run `receipt` on
  reviews you did not write.** There will be no 0.4.x patch: the fix is in
  0.5.0 and later only.

### Predicates: a claim names the numbers its artifact must show

```markdown
**Claim**: the suite runs 71 passing tests.
**Grounding**: VERIFIED[tests-a3f91c: exit=0, passed>=71, failed=0]
```

- Keys are a closed set read off the cited block itself - `exit`, `stopped`
  (`none` / `timeout` / `overflow` / `killed`), and the work-summary counts
  (`passed failed skipped todo`, `files ignored errors warnings`) - so a
  predicate checks identically locally and in CI.
- Nothing is dropped: an unknown key, a fragment that does not parse, a key
  given twice, a count the artifact does not carry, a non-decimal or unsafe
  number, or an ordering comparison on `stopped` is an error.
- A `VERIFIED[...]` bracket that is not an address is an error, instead of
  silently falling back to the legacy bare-`VERIFIED` proximity check.
- Predicates are checked in addition to the existing outcome rules, never
  instead of them, and the tag's text is removed before a claim's wording is
  read - `passed>=3` inside a failure claim no longer reads as success.
- Two different artifact blocks under one id are now an error (identical
  copies are fine). Previously the second was never looked at.
- The skeleton writes the predicates for you, read off the run it gathered.
- New negative fixture: `examples/plain-node-project/reviews/predicate-mismatch.md`.

### The seal: was this block gathered, and is it still about this code?

- Every `gatherEvidence()` now publishes a **sealed run** into the checkout's
  git directory (`git rev-parse --git-path evidence-layer`): the bundle, a
  canonical hash of every artifact block, and a fingerprint of the working
  directory's content - a git tree id computed through a throwaway index, so
  the real index is never touched. Committing unchanged content does not move
  it; writing the review does not either; editing any other non-ignored file
  does.
- A run becomes current only once it is complete. A gather that fails - or
  whose own steps write into the files they check, like a formatter or code
  generator - is never published; the bundle names the step and the paths, and
  `GatherResult` reports `sealed`, `runId`, `treeChanged` and `coverage`.
- `evidence-layer claims review.md --seal` adds two checks: every cited block
  must be one the current run produced, unedited, and the code must still be
  what that run saw. Editing a file after gathering is an error that names the
  file. An untracked file too large to hash, a sparse checkout or a split index
  makes freshness `unverifiable` - never a pass.
- `gatherEvidence({ seal: false })` turns it off; `reviewPaths` names the
  review files to leave out of the fingerprint (default `review.md`).
- Not an attestation: it catches the default failure, not a writer who means to
  fake it. CI, gathering its own evidence, stays the independent party.

### The runtime gate, for Claude Code

- **Session start** tells the agent the claim grammar and snapshots the review
  files, so a later stop checks only what this session wrote.
- **Before each file write**, a write into the gate's own ledger is refused -
  an accidental-write guard, not a sandbox.
- **At stop**, `claims`, `receipt`, provenance and freshness run over every
  review file the session changed, and over the `**Claim**:` lines of the
  agent's final reply, resolved against the sealed bundle. Ordinary prose is
  not graded. Errors block the stop, with the findings as the reason.
- A **retry episode** blocks at most twice, then lets the agent through with
  the errors attached; only a clean check closes it. The gate **fails open** by
  default; `--fail-closed`, `--keep-blocking` and `--strict` are the stricter
  trades.
- Every decision goes into a journal in the checkout's git directory. An allow
  that checked nothing is never recorded as a pass.
- Install with `npx evidence-layer init claude` (merges into
  `.claude/settings.json`, or `--local` for `settings.local.json`; keeps every
  hook that is not its own; idempotent), or as a plugin:

  ```text
  /plugin marketplace add AndrewBogdanovTSS/evidence-layer
  /plugin install evidence-layer@evidence-layer
  ```

- `evidence-layer hook claude <event>` always exits 0 and answers in Claude
  Code's own protocol, because Claude Code reads an exit code as a decision and
  this package's `2` (bad usage) is Claude Code's "block".
- The pre-write hook loads only what it needs (~55 ms on the development
  machine); session start and stop measured 70-100 ms. In a live Claude Code
  2.1.302 session the gate blocked an untagged claim, the agent fixed it, and
  the next stop went through.

### New commands and options

- `evidence-layer hook <host> <event>` - the gate, as a host's hook runs it.
- `evidence-layer init claude [--local] [--dry-run]` - set the gate up.
- `evidence-layer claims --seal [--repo <path>]` - hold cited blocks to the
  sealed run.
- `evidence-layer journal report --include-gate` - the gate's own counts:
  blocks (tagged real or false), clean stops, stops let through without a clean
  check, refused writes, median decision time.
- `evidence-layer journal tag <id> real|false --gate` - tag a gate block.

### API

- New exports: `parsePredicates`, `evaluatePredicates`, `suggestPredicates`;
  `sourceFingerprint`, `publishRun`, `readCurrentRun`, `checkProvenance`,
  `checkFreshness`, `canonicalBlock` and the rest of `seal`; `decide` and the
  gate types; `git` and `gitCapture`.
- `lintClaims` options: `artifactSource` (resolve ids against another
  document, such as a sealed bundle) and `prose: false` (grade only `**Claim**:`
  lines).
- `package.json` declares `"evidenceLayer": { "hookProtocol": 1 }`, which the
  plugin's launcher checks instead of comparing version strings.

### Performance

- The CLI loads each command only when it is the one asked for. Smoke prints
  the median cold start against a 100 ms budget (~51 ms on the development
  machine), as a number rather than a gate - timing on shared runners is noise
  as often as signal.

### Behaviour changes to check when upgrading

- `gatherEvidence` writes into the repository's git directory by default. Pass
  `seal: false` if that is unwanted.
- A `VERIFIED[...]` bracket that is not a valid address used to pass as bare
  `VERIFIED` with a warning; it is now an error.
- Two different blocks under one artifact id in one review are now an error.

### Governance

- [DEC-0005](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0005-runtime-gate.md)
  records eight invariants, each enforced by `pnpm test` or `pnpm check:docs`.
- `check:docs` now holds the README's supported-hosts table to an adapter with
  recorded fixtures.
- The boundary test covers `src/hosts/`: it imports only builtins, the core and
  its own contract, and the core never imports it.
- The suite is 356 tests across 26 files.
