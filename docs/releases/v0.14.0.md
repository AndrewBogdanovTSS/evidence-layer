## evidence-layer 0.14.0

A command's kind is read from what runs, not from the arguments it was given.
Nothing here changes what an exit code means.

### Artifacts

- **`classifyCommand` ignores paths, quoted strings and leading `NAME=value`
  environment assignments.** It matched against the whole command line, so a
  lint run over `src/typecheck.ts` was classified `types`, and a test run over
  `src/lint/` was classified `lint`. Besides the misleading id prefix and
  suggested claim ("Typecheck reports no errors" for a lint run), a test or lint
  run classified as anything else was exempt from the work-summary rules: a
  success claim on it was never held to its counts. Now
  `pnpm test src/typecheck.test.ts` is `tests`, and its success claims are.
- A file extension at the end of a token (`tsconfig.json`, `a...b`) or a path
  separator anywhere in it marks the token as an argument. Program names,
  subcommands and flags are still read: `node node_modules/nuxt/bin/nuxt.mjs
  typecheck` is `types`, `pnpm install --frozen-lockfile` is `lockfile`.
- An unquoted, path-free argument is still read as part of the invocation:
  `pnpm test -t typecheck` is `types`. Quote it.

### Behaviour changes to check when upgrading

- **Some artifact ids change.** The kind is the id's prefix, so a command whose
  kind came from an argument - for example `pnpm eslint src/typecheck.ts`, once
  `types-…`, now `lint-…` - gets a different id. An artifact generated with an
  earlier version and verified with this one fails its address check for those
  commands only; regenerate the evidence. Commands whose kind did not change
  keep their ids.
- **Success claims on those runs are now held to their work summary**, as any
  other lint or test run's are.
