## evidence-layer 0.19.0

Phase 0 of [the roadmap](../plans/review-and-roadmap-2026-11.md): what the
layer did not check is now said, and records it kept no clock on now have one.
Nothing new blocks by default, but three changes can turn a clean run red -
read **What you may have to do** first.

### What you may have to do

- **`claims --strict` without `--seal` or `--bundle` now fails a review that
  cites artifact blocks.** Such a run reports one new finding,
  `claims/provenance-unchecked`, at `unverifiable`: the blocks were held to
  nothing but the review itself, which a block typed by hand under an
  invented id satisfies. Without `--strict` the exit code is unchanged. Give
  the run the bundle the gather wrote (`--bundle`, or the action's `bundle:`
  input), or `--seal` in the checkout that gathered.
- **A `proposed` decision record needs a `decide_by` date.** Without one,
  `governance` reports `decisions/bad-decide-date`; past it,
  `decisions/undecided` - both errors. Add `decide_by: YYYY-MM-DD` to the
  frontmatter of each proposed record.
- **A receipt whose `Files in diff` is not what git counts now fails**, as
  `receipt/diff-count-mismatch`, with the right number as the fix. The count
  is over `<base>...<head>`, the commits the receipt names; files edited but
  not committed are not in it.

### Claims

- **Output that prints a fence stays inside its artifact block.** Fences are
  read by length, as CommonMark reads them, and an artifact block is written
  with a fence one longer than any backtick run in its output. Before, a test
  run printing a Markdown snippet broke its own block - its claim failed as
  `claims/unknown-artifact` - and output that printed an artifact block was
  parsed, and sealed, as one. The seal now holds only the artifacts the
  gatherer produced.
- **The grade mix is reported.** `claims` prints "Grades: 0 of 3 claims
  VERIFIED - ..." under its summary, leads the GitHub and Azure summaries
  with it, and its JSON report carries `grades` - **schema 6**. A review of
  honest UNVERIFIED claims still passes; it can now be told apart from one
  whose claims are verified.
- **Bare `VERIFIED` names its cutover date**, 2026-12-06
  (`BARE_VERIFIED_CUTOVER`), instead of a path in this repository. The first
  release on or after it makes `claims/bare-verified` an error.

### Gathering

- **The zero-config plan runs the project's own scripts, or skips them.**
  The lint, typecheck and test steps run through the package manager the
  `packageManager` field or the lockfile names (pnpm when neither does), and
  a step whose script `package.json` does not have is skipped with that
  reason. Before, an npm project with only a `test` script was handed
  "Lint reports violations" over a `command not found`.

### The runtime gate

- **Every stop is journalled.** A stop with no changed review and no
  `**Claim**:` line in the final reply is `nothing-to-check`: let through as
  before, with nothing said to the agent, and journalled as unverifiable.
  `journal report --include-gate` leads with "N of M stops checked
  something". A session that reported its results as prose used to leave no
  trace at all.

### Receipt and governance

- A receipt's counts are read as the first number in the field: "22 (1 not
  committed)" was read as 221.
- `governance` in a repository with no `package.json` reports
  `governance/no-manifest`, `unverifiable`, instead of crashing with exit 1.

### Repository

- `check:docs` checks every relative link in every tracked Markdown file, not
  only the README's. Four were broken.
- Statements past their date are corrected: the tour's command count and
  "three outcomes", the plugin's description of how often the gate blocks,
  the README's account of what the gate grades and of what a receipt proves.

New codes: `claims/provenance-unchecked`, `receipt/diff-count`,
`receipt/diff-count-mismatch`, `governance/no-manifest`,
`decisions/bad-decide-date`, `decisions/undecided`, `decisions/pending`.
