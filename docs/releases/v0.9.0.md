## evidence-layer 0.9.0

Claims in a project's own review format - a risk table's cells, a list - can
now be graded by the same rules as `**Claim**:` blocks, the distance a grade may
sit below its claim is the caller's to set, and `runAsync` takes its arguments
as an array. Each removes a workaround a consuming project had to write around
this package. Nothing here changes what an exit code means.

### Inline claims

```js
lintClaims(markdown, 'review.md', {
  inlineClaims: [{ line: 14, text: 'store leaks per request VERIFIED[tests-a3f91c: failed=0]' }],
})
```

- The caller finds the claims - its table grammar stays its own - and they get
  the address, commit, predicate, outcome and shotgun rules a `**Claim**:`
  block gets. A bare `VERIFIED` looks below its line for its block, as a block
  claim's does.
- An inline claim has no lines below it to borrow: a DOCUMENTED claim cites
  inside its own text, and an INFERRED one carries its reason beside the tag
  (`[INFERRED: fewer unique URLs -> more cache reuse]`). Two new reason codes:
  `claims/reasoned` and `claims/no-reason`.
- Inline claims count towards `claims/shotgun` together with the blocks, and a
  document whose only claims are inline is not reported as `claims/none`.
- A `line` outside the document is a `RangeError`: a finding that points
  nowhere helps nobody.

### Where a grade may sit: `gradeWindow`

- `lintClaims(md, file, { gradeWindow: 5 })` lets the grade sit up to that many
  lines of prose below the `**Claim**:` line. The default stays 2
  (`GRADE_WINDOW`); `0` means the claim line only.

### `runAsync(program, { args })`

- With `args`, nothing in an argument reaches a shell on POSIX. On Windows,
  where `pnpm` is a `.cmd` and needs one, each argument is quoted for cmd.exe;
  one containing `"` or `%` cannot be quoted reliably there and rejects the
  promise instead of running as something else.
- The result's `command` is the same line on every platform - POSIX-quoted
  where an argument needs it - because `artifactId` hashes it.
- Without `args`, nothing changes.

### Expiry dates, written down

- A governance exception expires, and a decision record goes stale, at 00:00
  UTC **on** the listed date - the listed day is the first one not covered, in
  every time zone. This was always the behaviour; it is now documented in
  `docs/governance-exceptions.md` and `docs/evidence-layer.md`, and the
  boundary is pinned by tests.

### Behaviour changes to check when upgrading

- **A fenced block between a claim and its grade no longer counts against the
  window, and cannot supply the grade.** A grade written below a code example
  used to be out of reach (`claims/untagged`); it is now found. A grade-like
  line inside a fence used to be taken as the grade; it no longer is.
- **The next `**Claim**:` line ends the search.** An untagged claim directly
  above a tagged one used to take that one's grade; it is now
  `claims/untagged`, which is what it was.

### API

- New: `GRADE_WINDOW`, `INLINE_REASON_WORDS`, `InlineClaim`;
  `LintOptions.gradeWindow` and `LintOptions.inlineClaims`;
  `RunAsyncOptions.args`. `findClaims` takes an optional window.
- Reason codes `claims/reasoned` and `claims/no-reason`.
