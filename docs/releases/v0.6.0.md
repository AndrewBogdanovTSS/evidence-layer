## evidence-layer 0.6.0

Every finding now says which rule produced it, in a word a program can match,
and the checks can print their findings as JSON. Until now a tool that wanted
to act on a finding had the level - how bad, not what - or the English
sentence, which changes whenever someone improves it. The decision is
[DEC-0006](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0006-reason-codes.md).
Nothing here changes what a review must contain or what any exit code means.

### Reason codes

- Every finding from `claims`, `receipt`, `claims --seal` and `governance`
  carries a `code` naming the rule behind it: `claims/predicate-unmet`,
  `claims/unknown-artifact`, `receipt/wrong-base`, `seal/stale`,
  `governance/unreached` and 65 more. The full list, with what each means, is
  in [`docs/evidence-layer.md`](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/evidence-layer.md#machine-readable-output).
- A code names a rule, not an outcome. The five levels are unchanged; a rule
  that can pass or fail has one code for the pass and one for each way it
  fails, so the code alone says what went wrong.
- A released code keeps its meaning. A rule whose meaning changes gets a new
  code; the suite fails if a released one is removed or renamed. `claim` and
  `detail` remain prose and may be reworded in any release.
- The package's own checks cannot produce a finding without a registered code:
  it is a type error. `Finding.code` stays optional for a project's own checks.

### `--format json`

```bash
npx evidence-layer claims review.md --format json
npx evidence-layer receipt review.md --format json
npx evidence-layer governance --format json
```

- Stdout is one JSON document and nothing else - no text, no delimiters - and
  the exit code is the one the text mode gives.
- The document is the report `governance` already printed between its
  `---GOVERNANCE-JSON-BEGIN---` delimiters, now **schema 4**: each finding has
  `code`, and the report has `check` (`claims`, `receipt`, `governance`). Both
  fields are additions; a reader of schema 3 still reads it.
- An unknown format is bad usage (exit 2), never a quiet fall back to text.

### The runtime gate runs in this repository

- `evidence-layer init claude`, run in evidence-layer's own repository, wires
  the plugin's launcher instead of `node_modules/evidence-layer`, and the
  launcher treats a directory whose own `package.json` is evidence-layer as
  the package. A checkout that has not been built says the gate is inactive
  and suggests `pnpm build`, rather than failing the hook. The repository now
  commits its `.claude/settings.json`, so every Claude Code session in it runs
  the gate.

### Fixes

- A `path:0` citation reported "resolves" while failing. It now says lines are
  numbered from 1.

### API

- New exports: `CODES`, `Code`, `CodedFinding`; `formatOf` and `Format`;
  `printJsonReport`. `buildReport` takes an optional `check`.
- `lintClaims`, `checkReceipt`, `checkProvenance`, `checkFreshness`,
  `checkReachability`, `checkExceptions` and `checkDecisionHygiene` return
  `CodedFinding` - a `Finding` with `code` set, so existing callers compile
  unchanged.
- `REPORT_SCHEMA` is 4.

### Repository

- `AGENTS.md` is the source of truth for contributors, people and agents;
  there is deliberately no `CLAUDE.md`, because Claude Code reads `AGENTS.md`
  when none exists.
- The suite is 365 tests across 27 files.
