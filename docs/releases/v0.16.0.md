## evidence-layer 0.16.0

CI's evidence can now cross jobs. A review written after the gather - by a
model in a later job, or by a person reading the uploaded bundle - is held to
the bundle CI gathered, and the gather can be a workflow's test run instead of
a second one. See [DEC-0011](https://github.com/AndrewBogdanovTSS/evidence-layer/blob/master/docs/decisions/0011-ci-evidence-crosses-jobs-as-a-bundle.md).

### Claims

- **`claims --bundle <file>`** holds every cited block to an evidence bundle
  file: the id must be one the bundle carries, and the block identical to it
  (`bundle/not-gathered`, `bundle/edited`, `bundle/provenance`;
  `bundle/broken` for a file that is not a bundle). Without it or `--seal`,
  a block typed by hand under an invented id passes `claims`, because an id
  cannot be recomputed from a trimmed block. A missing bundle file is exit 2.
  The commit under review falls back to the bundle's `- Head:` line after
  `--sha` and the receipt. Freshness is not checked: give `--sha` the commit.

### Gathering

- **`GatherResult.steps`** says how each planned step ended - exit code and
  stop reason, or why it was skipped - and **`stepFailed(step)`** reads one.
  A failing step still gets its block; nothing about the bundle changes.
- **`pnpm evidence` and the example's `scripts/evidence.mjs` exit 1 when a
  step failed**, after writing the bundle. A copy of the example script made
  before this release keeps exiting 0; add the exit check at its end to let CI
  run it instead of the test step.

### The action

- **`bundle` and `sha` inputs**, passed to every `claims` run. `bundle` with
  an installed evidence-layer older than this release is misconfigured rather
  than passed unchecked: the package declares `evidenceLayer.claimsAgainst`.

### The example project

- Its workflow gathers in CI - the suite once, inside the gather - uploads the
  bundle beside `governance` in parallel, and on a pull request has a model
  review from the bundle with no shell, holds that review to the bundle, marks
  what it does not back UNVERIFIED and posts it. Its README says which jobs to
  make required checks. Its invariant now names `npm run evidence`.
- `npm run ci:local` in the example runs those jobs locally the way CI runs
  them - `evidence` and `governance` side by side, `review` only once
  `evidence` passed, its checks reading the bundle from a separate directory -
  and prints what CI would report. The model step is read out of the
  workflow; `--review-skeleton` runs the pipeline with no model at all.
- This repository's CI runs that handoff across two runners on every push.
