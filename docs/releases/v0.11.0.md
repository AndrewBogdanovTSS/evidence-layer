## evidence-layer 0.11.0

A review posted as a pull request comment no longer has to open on command
logs. The claim and sample skeletons can put each artifact block, and the
Sample integrity table, in a `<details>` fold, with the Claim and Grounding
lines left outside it. The option is off by default, so existing output is
unchanged, and nothing here changes what an exit code means.

### Folded skeletons

```js
generateClaimSkeleton(artifacts, { fold: true })
generateSampleSkeleton(samples, omittedCount, { fold: true })
```

- Each artifact block sits under its Grounding line in a fold summarised as
  `📄 Output - <command> - exit N, L lines`, where L counts the block's lines
  between its fences and a stopped run reads `exit 124 (timeout)`.
- The Sample integrity table's fold summary takes the label's place and says
  how many files it quotes, never which. `parseReceipt` finds the table by its
  header row, so a folded receipt verifies as before.
- A summary never names a path. It sits outside every fence, so a verifier
  reading prose for citations would take a path there for a file the review
  cites. `summaryCommand` keeps environment assignments and drops
  `NODE_OPTIONS`, `--flags` and path-like words; the full command is still the
  block's first line.
- Every fold has an 8px spacer under its summary and blank lines around its
  content: CommonMark ends an HTML block only at a blank line, so without them
  the fence or table inside would not be read as Markdown. The native
  disclosure triangle is kept - it is the control's only affordance for
  keyboard and screen reader users.

### API

- New: `SkeletonOptions`, `foldDetails`, `summaryCommand`.
  `generateClaimSkeleton` and `generateSampleSkeleton` take an optional
  `SkeletonOptions`.
